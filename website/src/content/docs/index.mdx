UScreen Pro continues [UScreen by majmichu1](https://github.com/majmichu1/UScreen), the open-source way to turn an Android tablet into a real second monitor on Linux. The original gave Linux a display. **UScreen Pro makes it something you can live with every day**: a pen that behaves, a tablet that does not drain, a connection that sets itself up and heals itself, and errors that tell you what to do.

## Three ways to use the tablet

<CardGrid stagger>
  <Card title="Extended Display" icon="laptop">
    A real second monitor. A virtual display is created, encoded in hardware and streamed to the tablet; touch and pen come back.
  </Card>
  <Card title="Touchpad" icon="pointer">
    A laptop touchpad in your lap: native swipes and pinches, palm rejection, a right-click zone, adjustable sensitivity and shape. Nothing is streamed.
  </Card>
  <Card title="Stylus" icon="pencil">
    A pen tablet for the screen you are already looking at: pressure, tilt, eraser and buttons, with no display latency.
  </Card>
  <Card title="One mode per tablet" icon="setting">
    Every tablet has its own mode. Change the default once and every tablet without an override follows.
  </Card>
</CardGrid>

## The pen, done properly

<div class="split">
<div>

On most Linux setups a tablet pen is a compromise: a mouse that cannot draw, or a graphics tablet that cannot select text. UScreen Pro gives you both, **and lets the computer pick per app**.

| Style | The pen is |
| :--- | :--- |
| **Dynamic** (experimental, GNOME) | a pressure + tilt tablet in Krita, GIMP and the apps you list; a mouse in everything else |
| **Mouse** | always a pointer; the two side buttons can be right click, middle click or nothing |
| **Graphics tablet** | always a pressure, tilt and eraser tablet |

`Ctrl+Alt+P` or `uscreen toggle-tablet` flips the focused app by hand.

</div>
<div>

### Copy, cut and paste from the pen

Hold the pen still and a small menu opens right at the tip: **Cut, Copy, Paste, Select all, Undo**. It appears only over an app window, and only when there is a selection or something to paste. On GNOME it is drawn inside the Shell, so it is not a window and does not steal focus.

Under it, the stroke handling that makes a pen feel right: a *click slop* zone so a tap stays a tap, a *hover park* filter so a resting pen does not steal the cursor from your mouse, a cursor that is always visible even on Wayland, light taps that are not dropped, and a pointer snapped to whole pixels.

</div>
</div>

## Everything it does

The groups below are the short version. The complete table, with where each feature lives in the code and **whether it was run, only built, or inherited**, is [the full feature list](/UScreen-Pro/project/features/).

<div class="features">
<section>

### Display and speed

- A real EVDI monitor with the tablet's true size, right, left, above or below your screens
- Hardware encoding on NVENC and VAAPI, including HEVC on Intel and AMD, with `libx264` as the fallback
- The daemon **tests that an encoder can really encode a frame** and falls back by itself
- H.264, HEVC and 10-bit; tuned HEVC reached a 24.5 ms median encode-to-display time at 60 fps on the reference tablet
- Steady frame pacing, a Max performance mode, no ghost cursor, no lag crossing between screens
- Per-device encoder, frame rate, bitrate and position; several tablets at once, each isolated
- `uscreen doctor --latency` measures it on your machine

</section>
<section>

### Connection

- **USB** through adb: plug in and the display appears
- **Wireless in one click** from the wizard, with QR code or pairing code on Android 11 and newer
- **Tailscale** for when the LAN will not do <span class="tag">experimental</span>
- USB, Auto or Wi-Fi per device; the cable wins when both are there
- If the router blocks the tablet, the wizard says so and tells you how to fix it
- Loopback-only ports and a per-run session token

</section>
<section>

### Battery and power

- **Idle dimming** while your pointer is elsewhere, waking on any touch or pen input
- **Fade curves** from presets or a live Bezier **curve editor**, saved as your own
- **Battery saver**: two minutes without the computer and the tablet stops retrying and dims to 10 percent
- Optional lock with Device Admin, wake on touch, lock-screen options
- A black screen in Stylus mode so an OLED is not left lit

</section>
<section>

### Touchpad

- Move, tap, tap-and-drag, two-finger scroll, pinch, three- and four-finger swipes
- A **virtual multi-touch touchpad** on GNOME and KDE, so the desktop handles the gestures itself
- Right-click zone or two-finger tap; full-screen or rectangle shape
- Sensitivity from 50 to 200 percent, light haptic clicks
- Palm rejection and a switch to turn fingers off

</section>
<section>

### Updates and reliability

- **The tablet app updates itself** when it no longer matches the computer, through a queue, one tablet at a time
- Builds carry their git commit and a *dirty* flag
- A **compositor safety guard** keeps the virtual monitor from stalling your desktop
- `uscreen doctor` checks the machine, the tablet, the display and the settings and gives a hint for every failure
- A tray icon with the state, a graphics-tablet toggle and an update notice

</section>
<section>

### The tablet app

- Redesigned in Material 3, light, dark or follow the system
- Settings in four cards: Display and input, Connection, Power and battery, Advanced
- Immersive mode, cutout-aware layout, automatic or fixed orientation, stats overlay
- A pairing guide, and a decoder that recovers by itself instead of freezing

</section>
<section>

### The desktop app

- A new Tauri app with a five-step **device wizard**
- **Device pages** with an override switch on every row
- **System health**: daemon, build, device tools, Restart ADB, Force Reinstall APK
- Real Pause, Forget device, Start with desktop, light and dark themes

</section>
<section>

### Settings that follow you

- The tablet app and the desktop app edit the **same file**
- A global default and a per-device override for every setting
- **The newest change wins**, and a hand edit reaches the tablet in about a second
- Every tablet setting is also a row in the desktop app

</section>
<section>

### Built to be extended and checked

- A **tested installer** with a plan mode and a dry run
- One file for a distribution, one directory for a desktop, one row for a GNOME version
- Physical drawing tablets (XP-Pen, Wacom, Huion) through the same pen path
- Every function documented, and **62 experiments** published with what each one cannot tell you

</section>
</div>

## Errors that tell you what to do

Every failure the tablet or the wizard can meet has its own screen and its own button.

| You see | It means | The button |
| :--- | :--- | :--- |
| **Host Offline** | The daemon stopped or the connection dropped | Retry Connection |
| **Debugging Disabled** | USB debugging is off | Open Developer Options |
| **Connection Blocked by Router** | The router isolates clients | How to fix MAC randomization, Retry Setup |
| **Connection Paused by Host** | You paused this tablet | resumes when you do |
| **Updating** | The app is being replaced to match the computer | nothing; it comes back |
| **Version mismatch** | App and computer builds differ | Force Reinstall APK |

## Install

<Steps>

1. **On the Linux side**, from a checkout or an unpacked release:

   ```bash
   ./scripts/install.sh        # add --dry-run to see every command first
   ```

   It detects your distribution family, installs `ffmpeg`, `adb` and the EVDI virtual-display module, and puts everything else in your home directory.

2. **On the tablet**, install `uscreen.apk` and turn on USB debugging, or let the wizard do both.

3. **Plug in** and press Start in the desktop app (or run `uscreen start`). If something is off, run `uscreen doctor`.

</Steps>

## Honest status

The one setup this project has been run on is <b>Ubuntu 24.04 with GNOME 46 on Wayland</b>, with a Samsung Galaxy Tab S9 FE.
